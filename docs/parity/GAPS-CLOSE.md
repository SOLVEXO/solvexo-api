## 2. P8 gaps: DONE in code; verified on a real local Mongo + live over HTTP
- New webhook topics now fire from schema hooks (every write path, no service edited): `product.updated` (any real product write; view/rating counters ignored), `inventory.changed` (stock on-hand / reservation / damaged / in transit / expired moved; payload on_hand, committed, available), `customer.created` (store customers only: guest sessions and other stores excluded), `refund.created` (one event per refunded AMOUNT: each partial refund raises the running total, plus the full refund). Bursts of writes to one record are coalesced (1.5 s) and keyed per 30 s bucket; every delivery is routed by the record's OWN store and signed like the order events.
- Write API (`api/merchant/v1`): `PATCH products/:id` (status, tags only: an allow-list) and `POST inventory/adjust` (relative change through `InventoryService.adjustStock`, so location rows and the history row stay right). Both need an explicit `write_*` scope (a read token gets 403) and an `Idempotency-Key` header; the same key + same body returns the stored answer (`Idempotent-Replayed: true`) and has ONE effect; the same key with another body is 422; a failed attempt does not burn the key; keys expire after 24 h. Only the token's own store is reachable (another store's product/variant is "not found"). Each write is audited as actor `api_token`.
- Live check (API on the throw-away stack): read-only token refused, no key refused (400), replay and key reuse (200 / 422), stock +5 applied once (200 -> 205 with the same key sent twice), product.updated / inventory.changed / customer.created deliveries queued.
- BUG found on the way and fixed: the activity-log schema enum rejected the categories `khata`, `webhooks`, `api_tokens`, `api_token` and `b2b`, so audit entries written by the Khata, webhook/API-token and B2B code were silently dropped (only a server log error). Added the categories + a test that scans these modules for unknown categories (`activity-categories.spec`). Entries written before this fix are lost.
- Tests: `merchant-api.gaps.spec` (hooks matter-rules, topics routed per store + signature, refund per amount, idempotency, isolation, validation, audit call) with the existing P8 specs: 33 pass; permission-coverage passes.
