## P12 (`src/auth/member-two-factor.*`, `auth/member-two-factor.controller.ts`; web `/store/:id/security`)
- Built on the same TOTP helpers and recovery-code rules as the admin 2FA (`common/totp.util.ts`, `AdminTwoFactorService` untouched), for `seller` and `staff` kinds. State is in its own collection `member_two_factor` (secret AES-GCM, recovery codes SHA-256, never in the Seller/Staff document).
- Login: seller (`AuthService.login`) and staff (`StaffService.login`) answer `twoFactorRequired + challengeToken` (5 min, purpose-bound) after the password step; second step `POST api/auth/seller/2fa/verify` / `POST api/staff/2fa/verify` (throttled) issues the session. A password reset / suspension / token-version bump voids the challenge.
- Safety: a code works once (atomic step guard), recovery codes once, 5 wrong codes lock for 15 min (a right code is refused while locked), disable and new recovery codes need password AND a current code.
- Self-service `api/2fa/me` (status/setup/enable/disable/recovery-codes/step-up). Owner policy `PUT api/2fa/store/:storeId/policy` (`Store.requireStaffTwoFactor`); owner or platform admin reset `POST api/2fa/store/:storeId/staff/:staffId/reset` (audited in the activity log).
- Step-up: `POST api/2fa/me/step-up` (fresh code) returns a 10-minute token for header `x-step-up`; **enforced today on staff removal and on connecting an integration (payment gateway / courier credentials)** for members who have 2FA (members without it pass). The web client asks for the code with a browser prompt on `403 STEP_UP_REQUIRED` and retries.
- Web: second-step form on seller and staff login (`TwoFactorStep`), Security page (setup with key + link, recovery codes shown once, disable, new codes, owner switch "Ask staff to use two-factor"). No QR image (setup key / otpauth link only).
- Tests: `member-two-factor.spec.ts` 9 on real Mongo (setup, unreadable storage, replay, kind separation, lockout, recovery single use, disable/reset, challenge purpose, step-up) + staff/permission specs updated; web tsc + eslint clean. Not run: the login flows end to end, a real authenticator app, a browser.

## P12 NOT done / known gaps
- Step-up is NOT wired for email change, password change, courier-only routes outside `connect`, or other sensitive routes; owner "reset staff 2FA" has an API but no button in the Staff page.
- The staff policy is a soft flag: staff login says `twoFactorSetupRequired` and the app sends them to the Security page, but nothing blocks them from leaving it (a hard block needs a setup-only session).
- Seller 2FA does not cover Google/Apple social login or the POS PIN login. No 2FA for buyers.
- No en/ur strings (English literals); no rate limit per IP beyond the route throttles; no email to the person when 2FA is turned off or reset.
