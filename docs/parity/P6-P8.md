# P6 Product feeds, P8 Webhooks + API tokens (code; mock/real-Mongo tests only)

## P6 Product feeds (`src/product-feeds/`, web `/store/:id/sales-channels`)
- Per-store tokenized public URLs `api/public/feeds/:storeId/:token/google.xml` (Google Merchant RSS 2.0, `g:` namespace) and `meta.csv` (Meta catalog); no keys of ours. Off until the seller switches it on; wrong token / off / other store = the same 404; rotate = old URLs die. Optional `?currency=` only for the store currency or currencies the seller offered (converted with platform rates).
- One item per active variant of active physical products; `item_group_id` = product, availability from sellable stock (stock - committed - damaged - in transit - expired), unlimited stock, pre-order (with date), backorder (only if allowed), bundles limited by weakest component; compare-at price becomes `price` with the real price as `sale_price`; gtin only when 8/12/13/14 digits; brand = vendor; mpn = SKU; https images only; XML escaped, CSV formula-guarded.
- Health page lists variants missing title/description/image/price/link/brand-or-gtin (not sent until fixed). Max 5000 products per feed.
- Tests: 15 (mapping, availability, rendering, real-Mongo service). Not verified: Google/Meta actually accepting the feed (never uploaded), Meta CSV column names are from memory, per-market pricing beyond currency conversion, feed size/speed on big catalogs, no cache layer.

## P8 Webhooks + tokens (`src/merchant-api/`, web `/store/:id/developers`)
- Webhook subscriptions per store (max 10): https public domain only (no IP/localhost/port; DNS re-checked at send, redirects never followed), events order.created/paid/fulfilled/cancelled, refund.created, product.updated, inventory.changed, customer.created. Header `X-Solvexo-Signature: t=<unix>,v1=<HMAC-SHA256(secret, "t.body")>` (receiver should reject old `t`; helper `verifySignature` with 5 min tolerance), `X-Solvexo-Delivery` = stable event id for dedupe. Secret AES-GCM encrypted, shown once at create / rotate.
- Delivery: row per (subscription, event id) (unique, so an event is never queued twice), first attempt right away, retries after 1 min / 5 min / 30 min / 2 h / 6 h (cron every minute, Redis lock, claim per delivery), then failed; 15 failed deliveries in a row switch the subscription off; delivery log + manual redeliver; 30-day TTL. This is a DB-backed queue, not BullMQ.
- **Only the order events are wired** (via the existing Order write hook: created within 10 min of creation, paid, fulfilled, cancelled, refunded status -> `refund.created`). `product.updated`, `inventory.changed`, `customer.created` are accepted as subscriptions and `MerchantWebhooksService.emit()` exists, but no product/inventory/customer code calls it yet. Order events fire once per event type per order (a later cancel after fulfil still sends order.cancelled).
- API tokens (max 20 active): `sxk_` + 40 hex, SHA-256 at rest, shown once, revocable, 8 scopes (read/write for orders, products, customers, inventory), rate limit 120/min per token (in memory, per instance), audit log. Token endpoints today: `GET api/merchant/v1/orders` and `/products` (read only); **write scopes can be granted but no write endpoint exists yet**, customers/inventory endpoints not built. The store always comes from the token.
- Creating webhooks/tokens needs the plan's `apiWebhooksAllowed`; permission `settings.general.manage`.
- Tests: 15 (signature + replay window, backoff, URL rules, scopes, limiter; real Mongo: signed delivery once, store/event filtering, retry/backoff/fail, auto-disable, private-address refusal, redeliver/rotate, order events once, token hashing/scoping/revoke/isolation) with mocked fetch/DNS. Not verified: a real HTTPS receiver, multi-instance behaviour of the limiter, Nest DI boot.
