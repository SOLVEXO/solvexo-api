- Hooked into the existing storefront product search (`StoreService.getPublicStoreProducts`) and predictive search (`GET api/public/search/suggest`): without any config the behaviour is exactly the old one (the service is optional and never throws into search). Settings cached 30 s per instance.
- Public `GET api/public/search-config/:storeId` returns the filter settings. **Themes do not read it yet** (Maison still builds its own filters), and the marketplace-wide search (`api/search/products`) ignores synonyms.
- Tests: 14 pure + real Mongo (store isolation, own-products-only pins, validation, counters).
- Not verified: effect on real catalogs/ranking in a browser; pin ordering uses the collection-order branch (products not pinned keep their usual order after the pinned ones).
