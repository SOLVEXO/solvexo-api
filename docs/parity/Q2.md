## Local delivery
Already built (P-earlier): zone type `local_delivery`, postcode list / city fallback / radius km, `minOrderAmount`, `estimatedDeliveryTime`, free for the store to price. GAP fixed here: orders were not marked.
- `Checkout.localDelivery` + `localDeliveryEta` set when the chosen delivery is a local-delivery zone (not pickup, not a live carrier rate); `Order.localDelivery` + `localDeliveryEta` copied at order creation (`payment.service`).
- Seller: order detail shows a "Local delivery" card with the promised window; Orders list has a "Local delivery" filter (`?localDelivery=true`, server side). Order detail / buyer order payloads carry both fields.
- Test: `checkout/local-delivery.schema.spec.ts` (defaults, window kept, 120-char cap). tsc api + web clean. NOT tested: a full checkout through the real payment path with a local zone.

## Apple Pay / Google Pay
Gateway-config only, no wallet code of our own. PaymentIntents use `automatic_payment_methods: {enabled: true}` and every theme renders Stripe `PaymentElement`, so wallets appear automatically when (1) the seller's Stripe account has them enabled, (2) the page is https and the domain is registered for Apple Pay in Stripe (for each store host / custom domain), (3) the buyer's device has a wallet card. Nothing was run against Stripe; owner must register domains (Stripe Dashboard -> Payment method domains) and test on a real device. Other gateways (Safepay, PayFast, ...) show whatever their hosted page offers.
