# Q4 Product subscriptions / selling plans (implemented + tested at real-Mongo level; no real payment, no browser)

## Money model (important)
Solvexo never charges a card for a subscription. The only payment mode is `manual`: every renewal creates an ORDER the customer pays like any other (bank transfer / COD, the seller marks it paid). Gateways without recurring support are therefore not used at all; card-on-file renewals (Stripe/Safepay recurring) are NOT built (no adapter, no credentials; same status as `SUBSCRIPTION_PROVIDERS` in memberships). The contract stores `paymentMode: 'manual'` only.

## What exists
- **Plan groups** (`src/selling-plans/`): name, 1-6 delivery frequencies (every 1-12 weeks/months, each with its own 0-90% discount), trial days (days before the first order), optional max orders, products (+ optional variant limit), shipping per order, tax % per order (seller-set; checkout tax rules do not run for renewals). Archive instead of delete (running contracts keep going).
- **Contracts**: terms frozen at subscribe time, one item line (qty 1-99), delivery address, status active / paused / cancelled / completed, next billing date, cycles done, last order, dunning stage. Max 20 live contracts per customer per store.
- **Renewal engine** (cron `10 * * * *` with Redis lock, `renew()` callable directly): a unique `{contract, cycleNo}` row is the claim (parallel workers/re-runs create ONE order); orders are built through the existing draft-order path (stock decrement, ledger, unpaid `manual_bank_transfer` order), price = current variant price minus plan discount; after a long outage one order + next date in the future (no catch-up burst). Order that cannot be placed (stock/unavailable): no order, retry tomorrow, pause on the 3rd failure + email.
- **Dunning** (same cron): unpaid renewal order -> reminder at 3 and 5 days, auto-pause at 7 days (each stage claimed once). Channel: email (catalog events `subscription_renewal_placed`, `subscription_payment_reminder`, `subscription_paused`, switchable/editable in Settings -> Notifications). WhatsApp not wired.
- **Customer** (storefront): "Purchase options" box on the product page of Maison, Tech and Ledup (`core/subscriptions/SubscribeBox`, theme colours passed in, hidden when the product has no plan; sign-in required; address typed in the box) and `/subscriptions` page (`DefaultSubscriptionsPage`, every theme + Liquid): next order date, skip next, pause, resume, cancel (second click confirms). API also supports change frequency / address (no UI yet).
- **Seller**: sidebar Orders group -> **Subscriptions** (`/store/:id/subscriptions`): report cards (active, paused, cancelled 30 d, estimated monthly recurring), tabs Subscriptions (filter, pause/resume/cancel with confirm), Upcoming (next 14 days), Plans (create/edit/archive, product picker).
- **Permissions** `product_subscriptions.view/manage` (NOT the retired `subscriptions.*` keys; staff api+web registry, preset version 6). **Audit** category `subscriptions` (already registered). Public plans route is behind the password-store gate.
- **Strings**: 40 `sub.*` keys in en + ur + the API English copy (other 20 locales fall back to English).

## Tests run
- `selling-plans.integration.spec.ts` (real Mongo, direct calls): 15 tests: month math/discount/validation, plan tenant isolation + foreign products, public price preview, subscribe refusals, first order price/shipping/tax, trial, duplicate/parallel renewals, long outage, cancel/pause during cycle, max cycles, stock failure -> retry -> pause -> resume, dunning stages (once each, paid left alone), buyer controls + cross-customer/cross-store refusal, seller actions + report. `permission-coverage`, `customer-email*`, `ui-locales` specs pass.
- Web: `Subscriptions.test.tsx` (box + account page, 6), `SubscriptionsHub.test.tsx` (5); i18n tests; `tsc -b` + eslint clean on the new files. API `tsc` clean.

## NOT verified / limits
- Real draft-order completion was replaced by a fake in the spec (its stock logic has its own specs); no run through real Stripe/COD checkout, real SMTP, real Redis cron, or a browser.
- Renewal tax = the plan's flat %; no per-region tax, no shipping zones; one product line per subscription (no multi-item contracts); no seller-side address/frequency edit; change-frequency/address have API but no storefront UI; no plan-feature flag in entitlements; "monthly recurring" is an estimate from current prices.
