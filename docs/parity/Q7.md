# Q7 App platform (minimal) — implemented + tested at real-Mongo / component level; no real app, no browser

Developer docs: `docs/parity/app-platform.md`.

## What exists (`src/app-platform/`, separate from the older `src/apps/` online-store catalog, which is untouched)
- **Registry** (`AppDefinition`, admin only, `config.manage`): name, redirect addresses (<= 5, https public domains, exact match), requested scopes (merchant-API scopes), optional app webhook + events, uninstall webhook, dashboard page. `clientId` public; client secret stored as SHA-256, session secret AES-GCM; both shown once (rotate = new pair). Status draft -> approved <-> suspended. **Suspend removes the app from every store at once** (installs closed, tokens revoked, webhooks deleted, uninstall webhook sent).
- **Consent + code**: `GET authorize-preview` / `POST authorize` (owner/staff with `apps.manage`, plan must include API & webhooks, max 20 installed apps): server validates app approved, exact registered redirect, REQUIRED state, scopes subset of what the app registered, store exists; issues a single-use code (hash stored, 10 min, bound to store/app/redirect/scopes).
- **Token exchange** (public, throttled, `POST api/app-platform/oauth/token`): needs client id + secret (same 401 for unknown app and wrong secret, constant-time compare), then atomically claims the code (single use also under parallel calls; app/redirect must match). Creates the install, ONE `ApiToken` with exactly the granted scopes (reuse of the merchant API: `ApiTokenGuard`, rate limit, revoke) and ONE `WebhookSubscription` for the app's events (reuse: delivery/retry/signature); both carry `appInstallId`. Reinstall replaces the old install first.
- **Uninstall** (owner) and **suspend** (admin): conditional claim, token revoked (guard answers 401 at once), webhook deleted, signed `app.uninstalled` POST (public host check, 1 attempt), audit.
- **Dashboard embed**: `POST installs/:id/session-token` -> HS256 JWT (5 min, signed with the app's session secret, claims aud/sub/store/install); the web page shows a sandboxed iframe and answers `solvexo:ready` / `solvexo:session-request` ONLY from that iframe and exact origin.
- **UI**: seller Connected apps (Installed / Available, consent page, embed page); admin App platform page (register, edit, approve, suspend, new secrets). Permissions `apps.view/manage` (staff registry api+web, preset v9: Store Manager view). Audit category `apps` (authorized, installed, uninstalled, suspended). Merchant token/webhook limits ignore app-owned rows.

## Tests run
- `app-platform.integration.spec.ts` 15 (pure: https/redirect/scope/validation/session-token; real Mongo: secrets never listed, draft not installable, consent refusals (prefix/other-domain redirects, bad state, extra scope, unknown store), plan gate, code exchange refusals + single use incl. parallel + expiry, token/webhook created hashed/encrypted, tenant isolation, app token obeys scopes through the real `ApiTokenGuard` and dies on uninstall, uninstall cleanup + one uninstall webhook, reinstall replaces, suspend cascades across stores, session token only for installed app of this store). Related: `merchant-api` (2 suites), `permission-coverage`, `activity-categories` pass. API `tsc` clean.
- Web: `appPlatform.test.tsx` 7 (hub, consent page, embed handshake origin/source checks), `AdminAppPlatform.test.tsx` 4; `tsc -b` + eslint clean on the new files.

## NOT verified / limits
- No real third-party app, no browser (iframe sandbox + postMessage were only tested in jsdom), no real DNS check for the uninstall webhook (the sender is replaced in the spec). Access tokens do not expire (until uninstall/revoke); no refresh tokens. Scopes are the merchant-API scopes only. Apps are registered by Solvexo admins only. The seller consent page and the embed page do not re-check the plan in the UI beyond the sidebar gate (the server does).
